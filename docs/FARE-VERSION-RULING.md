# 裁决记录 TRAP-27：票价调整时点跨换乘链的版本接管

## 一、争议

一条换乘链可能跨过票价调整生效时点。两种朴素口径互相冲突：

1. **新价从刷卡时点接管（按腿选版）**：生效时点之后尚未开始的行程立即用新价，但同一链中途换版，似乎会让换乘锚点、优惠和日封顶"改口径"。
2. **整条链沿用起始票价版（锁版）**：口径一致，但已经公布的调整要等次日才落地，生效时点之后的行程仍按旧价结算。

## 二、裁决

**采用口径 1：票价版在每条行程的刷卡时点按本腿接管，不按整条换乘链锁定起始版。**

理由：

- 票价表的生效区间是 `[start, end)` 半开区间，公布即承诺"生效时点起按新价"。锁版会让生效时点之后、当日尚未发生的刷卡仍按旧价扣费，构成已公布调整不落地，且对运营方与乘客都不可解释。
- "中途改口径"是可以消除的伪问题：**换乘锚点、优惠与日封顶并不要求同价**，只要求每个环节引用其输入腿在刷卡时点裁决出的同一票价版。锚点是时间窗与换线判定的事实引用，不是定价口径；优惠参数按本腿票价版取；日封顶是卡/业务日维度的累计钱包，跨版连续累计、不清零。
- 每条腿的选版依据（刷卡时间 + 命中的生效窗）随记录留存，跨版链在页面显式标记，复核员可逐腿解释为何采用该票价版。

## 三、统一口径（四个环节引用同一票价版）

| 环节 | 票价版引用方式 |
|---|---|
| M3 票价版本 | 按本腿 `event_time` 落入的 `[start,end)` 窗选版，写入 `fare_version` 与 `fare_basis` |
| M4 行程配对 | 同卡同业务日连续成功行程构成一条换乘链；`chain_versions` 记录链内版本序，`chain_cross_version` 标记跨版 |
| M5 优惠回算 | 换乘优惠/换乘窗/日封顶参数按本腿 `fare_version` 取（`version_params` 可分版公布，缺省回退全局参数）；锚点保留其原票价版，仅用于 60 分钟半开窗与换线判定；日封顶跨版累计 |
| M6 清分对账 | 差额逐腿按其票价版计算，并输出 `per_version` 分版应扣/实扣/差额，分版合计等于总额 |
| M7 日结归档 | 直接复用 M6 的 `per_version` 作为 `settlement_versions`，并把票价窗快照封存入 `sha256`，保证链、优惠、清分、日结指向同一票价版 |

守恒式不变：每条腿 `基础票价 = 应扣 + 换乘优惠 + 封顶优惠`，Decimal 计算、分币守恒。

## 四、唯一可发布结果与运行保障

1. **内容寻址幂等**：`run_id = sha256(原始输入 + 参数 + 规则版本)`。同一调整重跑得到同一 `run_id`，保存层 `INSERT` 已存在即幂等复用，**不新增第二份、不覆盖 payload/version/decision**。
2. **切换失败保住上一版**：票价窗整表校验（字段齐备、金额非负、时间升序、无缝、不重叠）不通过时抛 `FARE_WINDOW_INVALID`，计算在写库前整体失败；事务回滚，上一版已发布结果保持可读，历史批次不增加。
3. **已发布结果不可覆盖**：复核走乐观锁条件更新，陈旧版本号返回 409（TRAP-26 既有约束保持）。
4. **原始刷卡与变化依据不丢失**：M1 原始行、`_sources` 来源行号、隔离原因全程保留；证据导出在 accepted/quarantine 之外新增 `fare_window`（生效窗快照）与 `settlement_version`（分版日结口径）两类证据行。
5. **当日唯一结算**：同一业务日、同一卡链的所有腿在一次流水线内完成裁决并封存一个 `sha256`，不存在两份可发布日结。

## 五、演示样例

`sample_data/switch.csv` 配套参数见 `app/pipeline.py::SWITCH_PARAMS`：调整时点设在 `2026-11-16T08:00:00+08:00`，使同一业务日内出现真实跨版链。

- 卡 0100：07:50 F1 首程 → 08:05 F2 换乘腿 → 08:20 F2 第三程，链版本序 `F1>F2>F2`。
- 卡 0500：07:58 F1 → **08:00 当刻 F2**（半开区间边界，当刻即新版接管）。
- 另含旧版独立链、新版独立链各一条，以及失败刷卡、缺金额两条隔离行。

页面在 `/fares`、`/journeys`、`/discounts`、`/clearing`、`/settlement` 均显示"票价版裁决"面板、生效票价窗、分版口径结算，跨版链行高亮。

## 六、已知边界

- 业务日按 Asia/Shanghai 划分；跨业务日的连续刷卡自然分属不同链与不同日封顶钱包，本裁决不改变该边界。
- 票价窗仅接受无缝 `[start,end)` 区间；出现缝隙或重叠一律整批拒绝，不做"猜测选版"。
